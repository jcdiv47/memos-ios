Memos for iPhone · design proposal

Activity colors and the Library screen

Two fixes and a small color system to hold them. The heatmap moves to a stepped scale whose levels are evenly spaced in contrast, and dark mode moves from blue-grey slate to a warm graphite that matches the paper of light mode. The Library gets the layout the original spec drew: activity at the top and a full bottom row. Pick a scale and a Library layout, then tell me in chat which ones to build.

1 · Why the heatmap looks flat

Most of the range is spent on the first step

Today a day's square is Memos Blue at an opacity of 25% plus 75% × count ÷ busiest day. With one 9-memo day, a 1-memo day and a 2-memo day get 33% and 42%, which look the same. Empty days use Paper 2, which in dark mode is darker than the page, so the grid reads as holes rather than a calendar. The numbers between the swatches are WCAG contrast ratios between neighbouring levels.

Current

Proposed

  • Four fixed levels instead of a continuous opacity. The cut points are the quartiles of your active days, so one 20-memo day doesn't push everything else to the bottom level.
  • Every level is an opaque color picked in OKLCH, with lightness spaced so each step is about 1.6–1.8:1 from the next. In dark mode more memos means brighter; in light mode, darker.
  • Empty days sit one step above the card (the new Fill token), so the calendar's shape is visible in both modes. Today gets an ink ring, which also works with the Graphite scale.
2 · Color system

Warm graphite for dark mode, plus two new tokens

Light mode already has warm paper and ink. Dark mode switched to cool blue-grey, so the app changed character between modes and the blue accent had nothing to stand out against. The proposed dark neutrals keep the same warm hue as light mode at very low chroma, and depth goes the iOS way: surfaces get lighter as they come forward. Contrast is measured against Card.

  • Fill replaces Paper 2 for wells and chips. It's darker than Card in light mode and lighter in dark mode, like the system's tertiary fill. Paper 2 stays only for code blocks, where a recessed look is right.
  • Ink 3 is new, for chevrons, zero counts and placeholders. Chevrons currently use Hairline, which measures about 1.2:1 on Card in dark mode and nearly disappears.
  • Activity 1–4 is its own ramp in Theme.swift, next to CodePalette, with Increase Contrast variants. The widget uses it in full color and keeps opacity steps (30, 50, 75, 100%) for tinted Home Screens.
3 · Activity screen

A calendar you can read at a glance

Month and weekday labels give the grid its dates, a legend explains the steps, and three figures above it answer the questions people actually open this screen for. The month list gets bars on the same scale.

4 · Library

Three ways to finish the bottom of the screen

The Library has two problems at the bottom. The list ends about 60% of the way down, leaving an empty slab. Below that, the capture field floats alone in the middle of the bottom bar, because the Search circle from the spec never made it in. Each option fixes both. Row counts are yours, from the screenshot; the activity grid is sample data.

5 · What changes in the code

Where each piece lands

Color assets

Retune the dark values of Paper, Card, Hairline, Ink 2 and Memos Blue. Add Fill and Ink3 colorsets, each with Increase Contrast variants.

Activity scale

MemoActivity.level(on:) returns 0–4 from quartiles, replacing intensity. ActivityPalette in Theme.swift maps levels to colors.

Activity screen

ActivityView gets the stats card, month and weekday labels, the legend, the today ring and month bars.

Library

LibraryView takes the chosen layout. The bottom bar adds DefaultToolbarItem(kind: .search, placement: .bottomBar) beside CaptureField.

Widget

ActivityWidget uses the same levels: palette colors in full color, stepped opacity when the Home Screen is tinted.

Rows everywhere

Chevrons and zero counts use Ink 3, so they stay visible without competing with the labels.
